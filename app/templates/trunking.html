Trunking & voice channels

One Pi runs the control channel and the network hub; every extra Pi joins as a voice channel with a short pairing code over Tailscale. The control Pi assigns the channel number, writes its voice-channel list and restarts dvmhost.

{% set role = st.role %} {% if role == "control" %}

Add a voice channel

  1. Install Malinois Link Control on the new Pi and open its Setup.
  2. Choose Add this Pi as a voice channel.
  3. Enter this Pi's address and the code below (valid 10 minutes, single use).

Channels in this system

Use Remove / unpair to drop a voice channel: this Pi's config is rewritten and the voice Pi is told to release itself (if it's online).

{% elif role == "voice" %}

This Pi is a voice channel

To leave the system use Unpair this Pi (also on the Dashboard). The control Pi is told to drop this channel if it can be reached.

{% else %}

Make this Pi a control channel

Pairing API & generated keys 
POST   /api/pairing/codes                       (control)  -> {code, expires}
POST   /api/pairing/claim  {code,name,url,rpc_address?,requested_tx_mhz?}  (control, called by new Pi)
       -> {channelNo, iden, iden_table, site, talkgroups, rpc{address,port,password}, network{...}, cluster_key}
POST   /api/pairing/join   {control_url, code, name, modem_*, requested_tx_mhz?, ack_*}  (new Pi)
GET    /api/pairing/voice-channels             POST /api/pairing/voice-channels/{chNo}/unpair  POST /api/pairing/reset
GET    /api/local/snapshot | /api/local/logs   (X-Malilink-Cluster-Key) -> dashboard aggregation

Control: protocols.p25.control.enable=true, dedicated=true; system.config.authoritative=true,
         supervisor=true; network.rpcAddress=0.0.0.0; system.config.voiceChNo=[each VC]
Voice:   protocols.p25.control.enable=false; authoritative=false, supervisor=false;
         system.config.controlCh {rpcAddress=CC, rpcPort=9890, rpcPassword, notifyEnable=true};
         network -> control Pi's dvmfne; one shared rpcPassword for all RPC peers
